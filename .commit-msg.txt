feat: read host versions and export surfaces from the running app (W1-3..W1-6)

The whole reason a packaged desktop install produced no import/peer findings
was that those detectors compared against profiles/node_modules, while the
running app serves its bundles from its own archive. Three pieces now close
that gap:

hostroot.ts — locates the running host. Inside the packaged app execPath is
the Electron binary, so the archive is found beside it; when auditing from a
plain Node process that is false, so known install roots (Windows/macOS/Linux,
plus DSH_INSTALL_ROOT) are tried in order. Every candidate whose bundled tree
cannot be found is skipped rather than assumed.

surface.ts — walks one package's export surface from a single entry: a .d.ts
when present, else the exports/main JS entry, else a directory union. Follows
export */named re-exports and relative imports through a bounded closure with
cycle detection, and reads CJS shapes too (exports.x =, module.exports = {...},
Object.defineProperty(exports, ...)), because bundled packages routinely ship
CJS whatever their manifest says.

hostface.ts — binds the archive to the walker.

Bugs found only by measuring against the real 121 MB archive, each now covered
by a test:

- Manifest paths are written "./lib/index.js"; naive concatenation produced
  pkg/./lib/index.js, which made the walker take package.json as its entry and
  report EVERY host symbol missing. Paths are now normalised.
- Shipped builds strip .d.ts, so exports.types almost never resolves in an
  installed app; it falls through to the JS entry instead of giving up.
- @deepseek-ai/dsh-base genuinely exports nothing ("export {};"). Zero names is
  the truth there, so the union fallback reports incomplete rather than letting
  an empty surface be read as "everything is missing".
- The union shared its visited set with the entry walk, but that set tracked
  FILES while the union visits DIRECTORIES: a flat package hung in an unbounded
  loop. Separate visited sets and a depth cap.

Verified live: 500 bundles read from the archive. Disk says dsh-base 0.1.0-rc.6
while the running host is 0.2.0-rc.2 — that gap is the W1 problem statement,
now measurable instead of guessed.

Adds Part E (10 checks): the fixtures reproduce real package shapes, and E3
documents that `B as default` exports only `default` — asserting otherwise
would have encoded a false positive. 57/57 checks pass.
